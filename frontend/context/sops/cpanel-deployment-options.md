# 🚀 Next.js ডেপ্লয়মেন্ট মাস্টার গাইড: cPanel, VPS এবং Serverless

> [!NOTE]
> **এই SOP সম্পর্কে**  
> এই গাইডে Next.js অ্যাপ্লিকেশন ডেপ্লয় করার সব ধরনের সম্ভাব্য উপায় নিয়ে আলোচনা করা হয়েছে। এখানে FTP-এর সীমাবদ্ধতা (যা `node_modules`-এর মতো হাজার হাজার ছোট ফাইলের কারণে অত্যন্ত ধীরগতির) এবং SSH, Docker ও Cloud PaaS-এর মতো আধুনিক বিকল্পগুলোর সুবিধা-অসুবিধা ব্যাখ্যা করা হয়েছে।

---

## 🏗️ ১. cPanel (Shared Hosting) অপশনসমূহ

যেহেতু আপনি cPanel-এ থাকার সিদ্ধান্ত নিয়েছেন, নিচে আপনার জন্য উপলব্ধ অপশনগুলো দেওয়া হলো:

### ১A. ম্যানুয়াল ZIP আপলোড (আমাদের বর্তমান পদ্ধতি)
GitHub প্রজেক্টটি বিল্ড করবে -> একটি `.zip` তৈরি করবে -> আপনি সেটি ডাউনলোড করে cPanel File Manager-এ আপলোড ও এক্সট্র্যাক্ট করবেন।
- **✅ সুবিধা:** cPanel সার্ভারে কোনো লোড পড়ে না, এটি অত্যন্ত নিরাপদ। ফাইল-বাই-ফাইল ট্রান্সফারের মতো ধীরগতি নেই।
- **❌ অসুবিধা:** প্রতিটি আপডেটের জন্য আপনাকে ম্যানুয়াল কাজ করতে হবে।
- **🔗 গাইড লিংক:** [SOP 07: cPanel Deployment (Bangla)](./cpanel-deployment-bangla.md)

### ১B. স্বয়ংক্রিয় FTP (GitHub Actions এর মাধ্যমে)
GitHub প্রজেক্ট বিল্ড করবে -> স্বয়ংক্রিয়ভাবে FTP-এর মাধ্যমে ফাইলগুলো cPanel-এ পাঠাবে।
- **✅ সুবিধা:** পুরোটাই অটোমেটেড।
- **❌ অসুবিধা (সবচেয়ে বড় সমস্যা):** FTP ফাইলগুলো একটা একটা করে পাঠায়। Next.js প্রজেক্টে `node_modules` এবং `.next`-এ ১০,০০০-এর বেশি ফাইল তৈরি হয়। **FTP-এর মাধ্যমে এত ফাইল পাঠাতে প্রচুর সময় (মাঝে মাঝে ৩০ মিনিটের বেশি) লাগে এবং অনেক সময় কানেকশন ড্রপ হয়।** Node.js অ্যাপের জন্য এটি একেবারেই উপযুক্ত নয়।

### ১C. স্বয়ংক্রিয় SSH / Rsync (সেরা cPanel অটোমেশন)
FTP-এর পরিবর্তে, GitHub Actions একটি `.zip` তৈরি করে, **SCP/SSH** ব্যবহার করে মাত্র কয়েক সেকেন্ডে সেটি cPanel-এ পাঠায়, এবং স্বয়ংক্রিয়ভাবে আনজিপ ও সার্ভার রিস্টার্ট করার কমান্ড রান করে।
- **✅ সুবিধা:** অত্যন্ত দ্রুত (১০,০০০ ফাইলের বদলে মাত্র ১টি বড় জিপ ফাইল পাঠানো হয়)। পুরোটাই অটোমেটেড।
- **❌ অসুবিধা:** **আপনার cPanel-এ SSH/Terminal অ্যাক্সেস চালু থাকতে হবে।** নিরাপত্তার কারণে অনেক হোস্টিং প্রোভাইডার এটি বন্ধ রাখে।

### ১D. cPanel Git Version Control
cPanel সরাসরি GitHub-এর সাথে যুক্ত হয়ে সোর্স কোড পুল (Pull) করে।
- **✅ সুবিধা:** cPanel-এর বিল্ট-ইন ফিচার।
- **❌ অসুবিধা:** কোড পুল করার পর আপনাকে cPanel-এ `npm run build` রান করতে হবে। Next.js বিল্ড করার সময় প্রচুর CPU/RAM খরচ করে, যার কারণে Shared Hosting সার্ভারগুলো প্রায়ই ক্র্যাশ করে।

## 💻 ২. VPS (Virtual Private Server) / Cloud Hosting (যেমন: DigitalOcean, AWS, Linode)

যদি আপনি ভবিষ্যতে cPanel ছেড়ে ডেডিকেটেড VPS-এ শিফট করেন, তাহলে এন্টারপ্রাইজ লেভেলের অটোমেশন ব্যবহার করতে পারবেন।

### ২A. GitHub Actions + PM2 (Standard VPS)
GitHub Actions আপনার VPS-এ SSH-এর মাধ্যমে কানেক্ট করে, কোড পুল ও বিল্ড করে, এবং **PM2** ব্যবহার করে সার্ভার রিস্টার্ট করে দেয়।
- **✅ সুবিধা:** অত্যন্ত দ্রুত এবং শক্তিশালী, প্রচুর ট্রাফিক সহজে সামলাতে পারে।
- **❌ অসুবিধা:** লিনাক্স সার্ভার ম্যানেজমেন্ট স্কিল প্রয়োজন (Nginx সেটআপ, SSL কনফিগারেশন)।

### ২B. Docker Containers (ইন্ডাস্ট্রি স্ট্যান্ডার্ড)
GitHub Actions-এর মাধ্যমে আপনার অ্যাপটিকে একটি আইসোলেটেড "Docker Container"-এ প্যাক করা হয় এবং Docker Hub-এ পুশ করা হয়। আপনার সার্ভার শুধু সেই কন্টেইনারটি ডাউনলোড করে রান করে।
- **✅ সুবিধা:** "Run anywhere" গ্যারান্টি। জিরো ডাউনটাইম ডেপ্লয়মেন্ট। আপনার কম্পিউটারে চললে সার্ভারেও ১০০% চলবে।
- **❌ অসুবিধা:** শেখার কার্ভ (Learning Curve) একটু বেশি। VPS প্রয়োজন, cPanel-এ সম্ভব নয়।

## ☁️ ৩. Serverless / PaaS (Next.js-এর জন্য আদর্শ পদ্ধতি)

এই প্ল্যাটফর্মগুলো বিশেষভাবে Next.js এবং ফ্রন্টএন্ড ফ্রেমওয়ার্কগুলোর জন্য তৈরি।

### ৩A. Vercel (Next.js-এর স্রষ্টা)
আপনি Vercel-এ লগিন করে আপনার GitHub রিপো কানেক্ট করবেন, আর কোনো কাজ নেই।
- **কিভাবে কাজ করে:** গিটহাবে পুশ করার সাথে সাথে Vercel নিজে নিজে বিল্ড করে ২ মিনিটের মধ্যে সাইট লাইভ করে দেয়।
- **✅ সুবিধা:** জিরো কনফিগারেশন, অত্যন্ত দ্রুত, ফ্রি-টিয়ার খুবই ভালো।
- **❌ অসুবিধা:** ট্রাফিক অনেক বেড়ে গেলে পেইড প্ল্যানের খরচ বেশি হতে পারে।

### ৩B. Cloudflare Pages
Vercel-এর মতোই গিটহাবের সাথে সরাসরি কানেক্ট হয়।
- **✅ সুবিধা:** চমৎকার গ্লোবাল CDN, সস্তায় বা ফ্রিতে প্রচুর ব্যান্ডউইথ।
- **❌ অসুবিধা:** Next.js-এর সার্ভার-সাইড ফিচার (SSR/API) Cloudflare Workers-এ চালানোর জন্য কিছু আলাদা কনফিগারেশন প্রয়োজন।

## 🎯 CIB-এর জন্য বর্তমান করণীয় (যেহেতু আপনি cPanel-এ থাকতে চান)

1. **নিরাপদ উপায়:** যেহেতু আপনি cPanel-এ থাকতে চাচ্ছেন, বর্তমানের **[ম্যানুয়াল ZIP আপলোড (১A)](./cpanel-deployment-bangla.md)** পদ্ধতিটিই আপনার জন্য সবচেয়ে নিরাপদ। এটি FTP-এর ধীরগতি থেকে আপনাকে বাঁচাবে এবং সার্ভারের কোনো ক্ষতি করবে না।
2. **অটোমেশন চাইলে:** আপনার হোস্টিং প্রোভাইডারের (অথবা cPanel-এর টার্মিনাল অপশন) কাছে চেক করে দেখুন আপনার **SSH Access** আছে কিনা। যদি থাকে, তাহলে আমরা **১C (Automated SSH/Rsync)** সেটআপ করে ফেলতে পারি, যা আপনার কাজ ১০০% অটোমেটিক ও দ্রুত করে দেবে!
